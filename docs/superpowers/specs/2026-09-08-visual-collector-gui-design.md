# 可扩展商品采集桌面工具设计

## 目标

为现有采集项目增加一个 Windows 桌面图形界面。用户粘贴商品链接后，工具自动识别平台、启动对应采集流程、实时显示进度与日志，并在完成后展示商品摘要和结果目录入口。

本期只实现 1688 平台，但平台识别和采集流程必须通过适配器扩展，后续增加淘宝、京东等平台时不修改 GUI。

## 范围

本期包含：

- Windows 原生桌面窗口，使用 Python 标准库 Tkinter 和 ttk。
- 单条商品链接输入与自动平台识别。
- 可见模式启动 Chrome，方便用户处理登录或验证码。
- 后台采集、实时日志、阶段状态和确定型进度展示。
- 1688 页面保存、解析、资源下载和结构化 JSON 输出。
- 采集完成后的商品摘要与“打开结果目录”操作。
- 可扩展的平台适配器注册机制。
- UTF-8 无 BOM、CRLF 的双击启动批处理脚本。

本期不包含：

- 1688 以外平台的实际采集实现。
- 批量链接队列、定时任务、账号管理或代理池。
- 本地 Web 服务、PHP 服务或远程部署。
- 绕过验证码、登录控制或站点访问限制。

## 技术方案

采用 Tkinter 和 ttk 构建单窗口应用。该方案不增加 GUI 第三方依赖，与现有 Python 项目和 Windows 双击运行方式最匹配。

GUI 不直接调用 1688 专有逻辑。程序划分为以下组件：

1. `PlatformAdapter`：平台适配器接口，负责链接匹配、规范化、商品 ID 提取、页面采集、解析和结果加载。
2. `PlatformRegistry`：保存已注册适配器，按链接自动返回唯一匹配项。
3. `Alibaba1688Adapter`：本期唯一实现，复用 `utils.auto_collector` 和现有解析下载流程。
4. `CollectionService`：在工作线程中串联适配器步骤，通过事件队列报告日志、阶段、成功或失败。
5. `CollectorGUI`：只负责输入、状态、进度、日志、摘要和打开目录，不包含平台判断与爬取细节。

新增平台时，只需实现并注册一个新的适配器。注册中心找不到匹配项时返回“暂不支持该平台”，不会启动 Chrome。

## 界面设计

界面采用单页纵向操作路径：

1. 顶部为商品链接输入框和橙色“开始采集”主按钮。
2. 输入合法链接后显示识别到的平台；当前为“1688”。
3. 采集期间显示当前阶段、进度条和简短状态文本。
4. 下方左侧为深色实时日志区，自动滚动并允许用户复制内容。
5. 下方右侧为结果摘要，显示标题、价格、SKU 数、图片数、视频数和店铺。
6. 成功后启用“打开结果目录”按钮。

窗口默认尺寸适合普通 Windows 桌面，并设置合理的最小尺寸。键盘焦点、按钮禁用状态、状态颜色和文本提示共同表达状态，避免只依赖颜色。

## 数据流

1. 用户粘贴链接并点击“开始采集”。
2. 注册中心匹配平台；1688 适配器只接受 `detail.1688.com/offer/<数字>.html` 商品链接。
3. 适配器删除查询参数，将链接规范化为商品详情页标准地址并提取商品 ID。
4. GUI 禁用输入和开始按钮，创建后台工作线程。
5. 工作线程以可见 Chrome 模式保存渲染后的 HTML 到 `products/<商品ID>.html`。
6. 适配器调用现有解析下载流程，输出资源、属性页、URL 快捷方式和重建脚本到 `products/<商品ID>/`。
7. 适配器从保存的 HTML 生成 `product.json`。
8. 工作线程把结果摘要和目录发回 GUI；GUI 恢复可操作状态并展示结果。

Tkinter 控件只能由主线程更新。工作线程通过线程安全队列发送事件，主线程使用 `after()` 周期消费事件，保证采集期间窗口可响应。

## 统一结果格式

`products/<商品ID>/product.json` 使用 UTF-8，至少包含：

- `platform`、`product_id`、`source_url`、`normalized_url`
- `collected_at`
- `title`、`description`、`product_code`
- `price`、`attributes`、`sku_matrix`
- `shop_info`、`ship_from`、`sales_count`、`min_order`
- `resources`：主图、色卡图、详情图和视频 URL 列表
- `downloaded_files`：已落盘资源的相对路径和数量
- `platform_data`：平台特有但无法归入公共字段的数据

字段没有值时保留空值或空集合，不伪造页面未提供的数据。

## 日志与进度

采集事件分为“校验链接、启动浏览器、保存页面、解析数据、下载资源、生成结果、完成”七个阶段。进度条按阶段前进；资源下载阶段显示已发现和已落盘数量，不虚构无法获知的字节级进度。

现有采集代码输出的标准输出和错误输出会转发到日志区域。日志采用 UTF-8 解码，保留足够信息用于定位浏览器驱动、页面结构和下载失败问题。

## 异常处理

- 空链接、格式错误和不支持的平台在主线程中直接提示，不启动采集。
- Chrome 或 WebDriver 启动失败时显示失败状态，并保留底层错误日志。
- 页面内容过短、标题为登录或验证码页面时判定采集失败，不把它当作商品结果。
- 个别资源下载失败时保留已下载文件，在摘要中报告成功数和失败数。
- 工作线程的未捕获异常统一转换为失败事件，GUI 必须恢复输入和按钮。
- 用户在采集中关闭窗口时弹出确认；确认后终止当前子进程并关闭窗口，取消则继续采集。

## 启动方式与编码

新增双击启动脚本，使用当前项目虚拟环境中的 Python；虚拟环境不存在时给出清晰提示。脚本使用 UTF-8 无 BOM、CRLF，并在 `@echo off` 后执行 `chcp 65001 >nul`，与其他已修复批处理文件保持一致。

## 测试与验收

自动化测试覆盖：

- 1688 标准链接和带查询参数链接能匹配 `Alibaba1688Adapter` 并正确规范化。
- 淘宝、京东、空字符串和伪造域名不会误匹配。
- 注册中心能注册新适配器，且不需要修改 GUI。
- 工作线程事件按顺序进入队列，失败后界面状态可恢复。
- 结果摘要能处理完整字段和缺失字段。
- 关闭运行中窗口时执行确认和子进程清理路径。
- 所有批处理文件严格为 UTF-8 无 BOM、CRLF，且不含 Unicode 替换字符。

端到端验收使用指定的 1688 商品链接：Chrome 可见启动，窗口保持响应，日志持续刷新，最终能打开正确结果目录。目录内必须存在 `product.json`、属性页、重建脚本、主图、详情图和视频；结构化数据至少包含标题、三档阶梯价、18 个商品属性、12 个 SKU 和店铺信息。

## 成功标准

用户从双击启动到完成一次采集，只需要粘贴链接和点击一次按钮。平台判断、页面保存、解析下载和结果展示全部自动完成；失败时界面能明确说明失败阶段并允许再次尝试。
