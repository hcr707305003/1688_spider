# 1688 单商品采集设计

## 目标

使用本仓库现有能力采集商品 `1021866455459`。在页面实际公开且当前会话可访问的范围内，尽可能保留结构化商品信息和媒体资源，不采集店铺内其他商品或相关推荐。

目标页面采用去除广告追踪参数后的标准地址：

`https://detail.1688.com/offer/1021866455459.html`

## 方案选择

优先使用仓库原生的两段式流程：Selenium 获取完整渲染 HTML，随后由 `main.py` 和 1688 解析器提取数据并下载资源。这样最大限度复用现有实现，也保留可重复解析的原始页面。

如果匿名访问被登录页、验证码或风控页拦截，则切换到仓库的可视交互模式，让用户在项目专用浏览器配置中完成一次登录或验证，再继续同一商品的采集。不通过绕过验证码、伪造账号或高频请求规避平台限制。

不采用直接逆向接口作为首选，因为该方式偏离本项目的主要工作流，且接口签名和页面数据结构更容易变化。

## 组件与数据流

1. `utils/auto_collector.py` 启动 Chrome；不可用时按项目逻辑回退到 Edge。
2. 浏览器访问标准商品地址，等待主体加载并滚动页面以触发懒加载。
3. 将渲染后的页面保存为 `products/1021866455459.html`。
4. `main.py` 读取该 HTML，由 `utils/parsers/alibaba_parser.py` 提取主图、色卡图、详情图、视频、属性、价格、SKU、库存、标题、店铺、发货地、销量和起订量等可用字段。
5. 项目下载器将可访问的媒体保存到商品输出目录；数据库和项目既有缓存机制保存结构化结果。
6. 额外生成一份便于核验的采集摘要，记录实际获取字段、资源数量、缺失项及失败原因，不把缺失字段伪造为空间外数据。

## 输出边界

所有结果保存在仓库内的 `products` 或项目既有商品输出目录中，商品 ID 为 `1021866455459`。输出包括：

- 原始渲染 HTML；
- 项目生成的结构化数据、属性和数据库记录；
- 主图、色卡图、详情图和视频中可成功访问的文件；
- 本次运行日志与结果摘要。

不额外抓取推荐列表、搜索结果、店铺全量商品或买家隐私数据。

## 异常处理

- 遇到登录或验证码时暂停自动采集，保留当前状态并请求用户完成交互验证。
- 页面失效、下架或无权限访问时记录页面实际返回内容，不将错误页判定为成功。
- 单个媒体链接失败不终止其余资源下载；摘要中列出成功数和失败数。
- 若 1688 页面结构已变化，先确认原始 HTML 中是否存在目标数据，再对现有解析器做最小兼容修正。
- 不启动、停止或重启任何 PHP 服务。

## 验证标准

采集仅在以下检查完成后视为成功：

1. 保存的 HTML 对应商品 `1021866455459`，且不是登录页、验证码页或错误页。
2. 至少提取到有效商品标题和一种核心商品数据或资源；所有提取项均来自保存页面或页面公开资源。
3. 对已下载文件检查存在性、非零大小及基本文件类型；统计每类资源的成功与失败数量。
4. 对结构化输出抽查标题、商品 ID、价格/SKU、店铺和属性，明确标注页面未提供或无法访问的字段。
5. 运行相关 Python 静态编译检查；不为此任务启动 PHP 服务。

## Windows 批处理脚本编码

生成的 `rebuild.bat` 以及仓库内的 `start1688.bat`、`bp1688html.bat` 均使用 UTF-8 无 BOM 和 CRLF 换行，并在首行 `@echo off` 后执行 `chcp 65001 >nul`。这样既避免 UTF-8 BOM 干扰首条批处理命令，也让后续中文菜单在 `cmd.exe` 中按 UTF-8 显示。静态脚本中已经损坏的中文从仍保留正确文本的仓库历史版本恢复，命令流程保持不变。

修改生成器后重新生成本商品的重建脚本，并对三个批处理文件执行 UTF-8 解码、无 BOM、CRLF 和替换字符检查。`rebuild.bat` 通过预置选项 `5` 测试退出路径；两个静态启动脚本仅执行无参数或无 HTML 文件的安全路径。测试不得选择会删除或重建资源的菜单项。
