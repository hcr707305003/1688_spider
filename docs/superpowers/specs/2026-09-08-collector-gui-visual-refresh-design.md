# 商品链接自动采集工具 UI 视觉升级设计

## 背景

当前商品链接自动采集工具已经具备链接识别、采集进度、实时日志和结果摘要等完整能力，但界面层级偏平，品牌强调色使用较散，日志与结果区域缺少清晰的主次关系。本次升级仅改善桌面 GUI 的视觉呈现和状态反馈，不改变采集能力、数据结构或平台适配方式。

## 目标

- 建立现代、清晰、适合长时间使用的“专业工具台”视觉风格。
- 保持“粘贴链接 → 开始采集 → 查看进度 → 查看日志与结果”的单一路径。
- 让平台识别、当前阶段、成功和失败状态一眼可辨。
- 保持现有 Windows 便携版的依赖结构和打包方式。
- 使用与“专业工具台”一致的新应用图标替换默认打包图标。

## 非目标

- 不修改采集服务、1688 解析逻辑、下载逻辑或输出数据格式。
- 不增加登录、历史任务、多任务队列、主题切换或其他新功能。
- 不替换 Tkinter/ttk 技术栈，不引入新的 UI 依赖。
- 不在本次工作中制作 Linux 或 macOS 安装包。

## 视觉方向

采用已确认的 A 方案“专业工具台”。整体使用浅灰蓝背景、白色功能卡片、深色日志面板和克制的品牌橙色。橙色只用于主操作、当前进度和关键状态，避免大面积高饱和色造成视觉疲劳。

### 设计令牌

- 背景：冷灰蓝浅色表面，用于拉开窗口与卡片层级。
- 卡片：白色主表面，搭配清晰但低对比度的边框。
- 主文字：深蓝灰；次要文字：中性灰蓝。
- 强调色：橙色，用于“开始采集”、进度条和活动状态。
- 成功色：绿色；警告色：琥珀色；错误色：红色。
- 日志：深蓝黑背景，正文使用高对比度浅灰，状态行使用对应语义色。
- 字体：Microsoft YaHei UI；日志继续使用 Consolas。
- 间距：以 8px 为基础节奏，使用 8、16、24、32px 等层级。
- 卡片圆角：视觉上约 12px；控件高度保持易点击且不拥挤。

## 布局

### 顶部标题区

左侧显示应用名称和一句用途说明，右侧显示当前服务状态。服务状态包含文字，颜色仅作为辅助，避免只依赖颜色传达信息。

### 链接与进度卡

卡片第一行显示“商品链接”和平台识别结果。第二行包含占主要宽度的链接输入框和固定宽度的主按钮。第三部分显示当前阶段、简要说明、百分比和进度条。

输入框和按钮在正常窗口宽度下保持同一行。窗口接近最小宽度时，输入框优先获得可用空间，主按钮保持可读尺寸，不出现文字裁切。

### 内容区

内容区保持水平双栏：

- 左侧约占 65%，使用深色卡片展示实时日志，是运行过程中的视觉重心。
- 右侧约占 35%，使用白色卡片展示商品结果摘要和结果目录入口。

布局继续使用可调整分隔栏，允许用户按需要改变日志与结果区域宽度。

### 结果卡

结果卡依次展示商品标题、四项核心指标、店铺名称和“打开结果目录”按钮。价格使用橙色强调，其余数字使用主文字色。四项指标使用浅色小卡片形成稳定的二乘二网格。

## 交互与状态

### 准备状态

- 输入框获得初始焦点。
- 状态显示“准备就绪”，阶段说明提示用户粘贴商品链接。
- 结果指标显示占位符，结果目录按钮禁用。

### 平台识别

- 用户输入时继续调用现有 `CollectionService.prepare`。
- 识别成功后显示“已识别 · 1688”等明确文字。
- 链接为空、格式错误或平台不受支持时，在输入区域显示现有错误原因。

### 采集中

- 点击主按钮或按回车启动现有采集流程。
- 输入框和主按钮禁用，防止重复提交。
- 当前阶段、说明、百分比和进度条同步更新。
- 日志自动滚动到最新一行；不同语义的日志使用成功、处理中、警告和错误颜色。

### 成功状态

- 进度更新为 100%，状态显示“采集完成”。
- 结果卡更新商品摘要并形成明确视觉强调。
- 输出目录有效时启用“打开结果目录”。
- 输入框和主按钮恢复可用。

### 失败与取消

- 失败状态显示明确错误标题和可执行的简短说明，日志保留完整错误内容。
- 取消状态提示用户可以重新输入链接。
- 两种状态都恢复输入框和主按钮，不保留虚假的完成进度。

### 关闭窗口

继续使用现有关闭确认逻辑。采集运行中关闭窗口时先询问用户；确认后取消任务并关闭。

## 代码边界

主要修改限制在 `gui/url_collector_app.py`：

- 更新颜色、字体、间距和 ttk 样式。
- 调整现有控件布局和视觉层级。
- 为日志控件增加语义颜色标签，并在写入时选择标签。
- 保持 `CollectorGUI` 与 `CollectionService` 的现有接口不变。

如需测试界面状态转换，可在现有测试文件中补充纯函数或控件状态级测试，但不把采集逻辑搬入 GUI，也不创建新的框架层。

### 应用图标

- 图标采用橙色底板、白色链接符号和深蓝下载节点，保持小尺寸下的强轮廓。
- 保留可编辑的 `assets/app-icon.svg`，并生成包含 16 至 256px 多尺寸图层的 `assets/app-icon.ico`。
- PyInstaller 使用该 `.ico` 作为 GUI EXE 图标，并把它作为运行时资源打包，使 Tkinter 窗口也显示同一图标。
- 图标不包含小字、渐变、阴影或第三方商标。

## 数据流

数据流保持不变：

1. `url_var` 的变化触发平台识别。
2. 用户启动采集后，GUI 调用 `CollectionService.start`。
3. GUI 定时从服务事件队列读取 `CollectionEvent`。
4. 日志事件写入日志区；阶段事件更新状态和进度；成功事件生成摘要；错误或取消事件恢复控件。
5. 结果目录按钮只在输出路径实际存在时启用。

视觉状态仅消费现有事件，不改变事件含义和顺序。

## 错误处理

- 输入错误：输入区展示错误原因，并把焦点留在链接输入框。
- 运行错误：状态区展示简短错误，日志区保留完整信息。
- 输出目录缺失：保持按钮禁用；若目录随后不存在，继续使用现有错误对话框。
- 未识别的日志格式：使用默认日志颜色显示，不因着色失败影响日志内容。

## 验收标准

- 视觉呈现符合已确认的“专业工具台”方案。
- 准备、识别成功、采集中、完成、失败、取消六种状态均有文字反馈。
- 链接输入、回车启动、进度更新、实时日志、结果摘要、打开目录和关闭确认继续工作。
- 最小窗口尺寸下无主要控件遮挡或文字裁切。
- 中文界面与实时日志不出现编码回退。
- 不新增运行依赖，不改变便携版目录结构。
- EXE 文件和运行时窗口均使用新的多尺寸应用图标。
- 项目现有 18 项测试继续通过；新增的界面辅助逻辑具备相应测试。
- Python 源文件通过语法检查，PyInstaller 配置仍可解析。
