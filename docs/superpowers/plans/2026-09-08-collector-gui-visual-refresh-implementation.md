# 商品链接自动采集工具 UI 视觉升级实施计划

## 目标

按已确认的“专业工具台”方案升级 `gui/url_collector_app.py`，保持采集服务接口和现有功能不变。

## 步骤 1：锁定现有行为

- 运行项目自带环境下的 18 项测试。
- 检查 `build_summary`、事件处理、关闭确认和结果目录行为。
- 验证标准：改造前测试全部通过，改动不进入采集服务层。

## 步骤 2：建立视觉令牌与组件样式

- 调整背景、表面、边框、文字、品牌色和语义色。
- 为标题、状态徽标、输入框、主次按钮、指标卡和进度条建立统一样式。
- 配置日志语义标签，默认文本仍保持高对比度。
- 验证标准：颜色与字体集中定义，不新增第三方依赖。

## 步骤 3：重组单窗口布局

- 建立顶部品牌区、链接操作卡和日志/结果双栏。
- 保留可拖动分隔栏，输入框优先扩展，按钮保持固定可读宽度。
- 结果区域改为清晰的标题、指标卡、店铺信息和底部操作按钮。
- 验证标准：最小窗口尺寸下主要控件不遮挡、不裁切。

## 步骤 4：完善运行状态反馈

- 映射准备、识别成功、采集中、成功、取消和错误状态。
- 开始采集时禁用重复操作；结束后恢复输入与按钮。
- 根据日志文本语义选择成功、处理中、警告、错误或默认颜色。
- 验证标准：状态始终有文字说明，颜色仅作辅助。

## 步骤 5：测试与视觉验收

- 创建可编辑 SVG 图标源文件并转换为 16 至 256px 多尺寸 ICO。
- 在 PyInstaller EXE 配置和 Tkinter 运行时中引用同一图标。

- 为日志级别判定和摘要显示补充纯逻辑测试。
- 运行全部单元测试与 Python 语法检查。
- 启动 GUI，截取默认、最小尺寸和典型采集结果状态进行检查。
- 确认打包规格仍能包含 GUI 入口和现有依赖。
- 验证标准：全部测试通过，中文显示正常，现有打包定义测试通过。
